# Portfolio landing page - Overview

Public document. Behaviour only.

## What this is

The front door to the portfolio, built as a small side-scrolling game. Instead of a grid of
cards, there is a character the visitor moves around a scene, and projects are boxes they
walk up to and open.

The point is not the game. The point is that a visitor who has been sent a link will spend
about eight seconds deciding whether to look at anything, and being handed a character to
move is a better hook than a list of links.

## What it does

| Capability | Description |
| --- | --- |
| Move a character | Arrow keys or the equivalent letter keys, or on-screen buttons on a touch device |
| Show what is reachable | Project boxes highlight and animate when the character is close enough |
| Open a project | Press to open the highlighted box, or click any box directly |
| Mark what has been seen | Boxes the visitor has opened are marked as visited |
| Explain itself | Instructions and controls are on screen from the start |

## How to use it

Either walk the character up to a project box and press to open it, or ignore the game
entirely and click the box. Both work, and the second exists because plenty of visitors
will not want to play anything.

## What it does not do

- It does not describe the projects. A box is an icon and a name, and the visitor finds out
  what it is by opening it.
- It has no levels, score, progress, or ending. It is a navigation device shaped like a
  game.
- It does not collect anything, remember anything between visits, or require anything.
- It is not itself one of the projects.

## Requirements to run it

A browser. Nothing to install, no account, no server.

## The honest state of it

Two project boxes exist. The portfolio behind it contains considerably more than two
projects, so most of the work is currently unreachable from the front door. That gap is the
main thing wrong with the page, and it is recorded in the plan rather than glossed over.
