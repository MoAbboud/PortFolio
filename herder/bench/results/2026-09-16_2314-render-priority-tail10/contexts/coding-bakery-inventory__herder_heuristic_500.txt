## Project
- [constraint] No Redis - it's one more thing to run on a tiny box, and the nightly job has all night anyway.
- [constraint] Every stock change must record who made it and when.
- [constraint] I don't want Postgres for this.
- [constraint] Stock quantities are never allowed to go negative - a sale that would do that is rejected.
- [constraint] Shop managers won't log in to anything; the email to Marisol is the whole interface for this version.
- [constraint] Nothing leaves the back-office network - no cloud services for this system.
- [constraint] Each adjustment has to carry the person and the timestamp, no exceptions.
- [constraint] To say it again plainly: a negative stock figure must be impossible, and the write that would cause one gets refused.
- [constraint] Not done yet: I need to work out whether returns from shops go back into central stock.
