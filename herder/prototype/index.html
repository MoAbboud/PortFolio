The brief

What runs in your browser
  • Extract. Only what you said is read. A chat is mostly the assistant talking, and treating its suggestions as fact fills the memory with ideas you turned down.
  • Render. Constraints first, then decisions, then open threads. A model told the rules can behave correctly without every fact; one with the facts and not the rules cannot.
  • Residue. Sentences no entry captured, spending only the budget left over.

These are the same rules the real system runs - generated from its Python source, with a test that fails if they drift.

What this leaves out

Merge needs sentence embeddings and a DeBERTa cross-encoder - gigabytes of weights - so it stays on the server. It decides whether a new claim repeats a stored one, refines it, or retires it.

So this page can see that you changed your mind, using the same rule the real merge step uses, but not resolve which entry the change replaces. Load the sample and you can watch it happen.

Token counts here are estimates. The real pipeline counts with cl100k.

How it is measured

Eight long conversations, 261 facts written by hand, 40 of them false on purpose - suggestions refused and decisions later reversed.

At a 3,000-token budget the full pipeline recalls 0.88 of the true ones and carries none of the 40 false ones. A plain "summarise this" at the same budget manages 0.21; pasting the most recent text, 0.31.

A model extracts, a model answers and a model grades, so the answer key is hand-written and was audited blind. The grader disagrees with itself on about 3.4% of verdicts, which puts the noise floor near four facts - small differences are reported as no difference.
